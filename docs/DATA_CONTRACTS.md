# Data contracts

Every shape/dtype/unit/validity convention the library uses, in one place. If a value isn't documented here, treat that as a gap to fix, not as license to guess.

## Images

`left_image`/`right_image` (as passed to `process()`, or inside `StereoObservation`): `numpy.ndarray`, shape `(H, W)` grayscale or `(H, W, 3)` BGR (OpenCV convention — **not** RGB) or `(H, W, 4)` BGRA, `uint8`. Both images in a pair must share identical `(H, W)` — enforced by `utils.validation.require_matching_stereo_pair`, raises `ValueError`/`TypeError` otherwise. No implicit resizing anywhere in the library.

## `StereoObservation` (`models.StereoObservation`)

Optional convenience container — `process()` still takes `left_image`/`right_image` directly; use `process_observation()` to hand one of these to the pipeline instead.

| Field | Type | Notes |
|---|---|---|
| `left_image`, `right_image` | `np.ndarray` | as above |
| `left_timestamp`, `right_timestamp` | `Optional[float]` | **Opaque, caller-defined.** This library performs no unit conversion, synchronization, or skew checking on these — a caller using ROS time, wall-clock seconds, or a monotonic counter all work identically as far as this library is concerned. `left_timestamp` wins as the result's `timestamp` if both are set. |
| `observation_id` | `Optional[str]` | **Phase D2 — THE observation/transaction identity.** Opaque, immutable, caller-owned. DPE copies it verbatim onto `DepthPerceptionResult.observation_id` and `GeometryFrame.observation_id` and interprets it in no other way: it never generates, parses, normalizes, sequences, or branches on the value, and no temporal or geometric decision depends on it. `None` (default) means "no identity supplied" and is always legal. **Not a coordinate frame** — see `GeometryFrame.frame_id`. Validated only as "a non-empty `str`, or `None`". |
| `frame_id` | `Optional[str]` | **DEPRECATED — alias of `observation_id`.** Pre-D2 name for the same concept (it was documented as "caller-side observation identity" and was inert up to and including v1.1.1). As of D2 it supplies the observation identity whenever `observation_id` is `None`, so existing callers keep working and now get propagation for free. Setting **both** to different values raises `ValueError` — there is exactly one authoritative identity, exposed as `StereoObservation.resolved_observation_id`. Prefer `observation_id` in new code. |
| `motion_hint` | `Optional[temporal.MotionHint]` | **New in Level 4, Phase E1; consumed as of Phase E2.** `DepthPerceptionPipeline.process_observation()` forwards this into `process()`'s `motion_hint` parameter, associating it with the frame's `temporal.TemporalRecord` when `PipelineConfig.enable_temporal` is `True` — pure bookkeeping, no integration/algorithm reads its contents. `None` means "no motion hint for this frame," not an error. See `docs/LEVEL4_CONTRACTS.md`. |

## `StereoCalibration` (`calibration.StereoCalibration`)

Frozen, validated at construction (`__post_init__` raises `ValueError` on any violation below) — see `docs/CALIBRATION.md` for the full field-by-field breakdown and units. Loaded via `calibration.load_stereo_calibration(path)`, the only file-path-touching function in the library.

## `PipelineConfig` (`config.PipelineConfig`)

Plain dataclass, every tunable threshold in one place, validated at construction (`__post_init__`, added in this recovery pass — see `docs/IMPLEMENTATION_STATUS.md`). `PipelineConfig()` with no arguments reproduces the original hardware-desk-test tuned defaults exactly. See the class docstring in `src/depth_perception_engine/config/pipeline_config.py` for every field's meaning and unit. Level 4, Phase E2 added four fields — `enable_temporal: bool = False`, `temporal_max_records: int = 30`, `temporal_max_age_s: float = 1.0`, `temporal_gap_limit_s: float = 0.5` — all validated, all additive, `enable_temporal=False` reproducing pre-E2 behavior exactly. See "Bounded temporal history" below.

## `DepthPerceptionResult` (`models.DepthPerceptionResult`)

The one top-level output shape, returned by both `DepthPerceptionPipeline.process()`/`.process_observation()` and `pipeline.api.process_stereo_pair()`.

| Field | Type / shape | Unit | Validity convention |
|---|---|---|---|
| `disparity_map` | `float32`, `(H, W)` | pixels | Invalid pixels (no stereo correspondence found) are `<= 0`. **Not** OpenCV's raw fixed-point `int16` output — already divided by 16 into true pixel units. |
| `depth_map` | `float32`, `(H, W)` | **metres** | Invalid pixels are exactly `0.0`. Valid range is clamped to `[DepthEstimator.MIN_DEPTH_M, DepthEstimator.MAX_DEPTH_M]` = `[0.15, 8.0]` m for the project's 64mm-baseline rig; anything outside that range is zeroed as invalid rather than returned as an out-of-trust-range number. |
| `valid_disparity_mask` | `bool`, `(H, W)` | — | `disparity_map > 0`, computed once in `fusion.result_builder` (added in this recovery pass) rather than left for every caller to re-derive from the sign convention above. |
| `valid_depth_mask` | `bool`, `(H, W)` | — | `depth_map > 0`. |
| `traversability_mask` | `TraversabilityResult` | — | **Naming wart, not fixed in this pass** — despite the name, this is not a pixel mask; it's a per-region grid + navigation decision (see below). Left as-is because `mp01_perception` reads this field by name today; see `docs/IMPLEMENTATION_STATUS.md`. |
| `obstacles` | `ObstacleAssessment` | — | see below |
| `confidence` | `float` | `[0.0, 1.0]` | Mean of the traversability grid's per-region confidence scores; `0.0` if the grid is empty. Not a probability in any calibrated sense — a transparent aggregate of an already-computed signal. |
| `processing_time_ms` | `float` | milliseconds | Wall-clock time for one `process()` call (`time.perf_counter()`-based), excluding image acquisition (the caller's problem, not this library's). |
| `timestamp` | `Optional[float]` | caller-defined | `None` unless `left_timestamp`/`right_timestamp` was passed to `process()` — see `StereoObservation` above for the opaque-unit caveat. |
| `geometry` | `Optional[geometry.PointCloud]` | — | **New in Level 3, Phase E3.** `None` unless `PipelineConfig.enable_geometry` is `True` (default `False` — see "Geometry" below). When present, built by `geometry.PointCloudBuilder` from the same `raw_disparity`/`Q` `depth_map` was computed from — not a second, independent computation. |
| `temporal_admission_status` | `Optional[str]` | — | **New in Level 4, Phase E2.** `None` unless `PipelineConfig.enable_temporal` is `True` (default `False`). When present, one of `temporal.TemporalAdmissionStatus`'s plain string constants (`ACCEPTED`/`ACCEPTED_NEW_SEQUENCE`/`REJECTED_INVALID_TIMESTAMP`/`REJECTED_OLDER_TIMESTAMP`/`REJECTED_DUPLICATE_TIMESTAMP`), reporting whether this frame's timestamp was admitted into `DepthPerceptionPipeline`'s internal `temporal.TemporalHistory` buffer. Pure chronology metadata — never affects any other field on this result. See `docs/LEVEL4_CONTRACTS.md`/`docs/E2_TEMPORAL_HISTORY_PLAN.md`. |

### `TraversabilityResult`

`regions: Dict[str, RegionStats]` (e.g. `"TL".."BR"` for the default 3×3 grid — **not** a pixel-aligned array; this is the real granularity the underlying `RegionAnalyzer` computes, not forced into a same-shape-as-image mask that would misrepresent it) + `decision: NavigationDecision` (one global enum value derived from the whole grid).

`RegionStats` (`traversability.types.RegionStats`) per-region fields include `classification` (`RegionClass` enum: `CLEAR`, `OBSTACLE`, `PROBABLE_WALL`, `LOW_TEXTURE_UNKNOWN`, `LOW_CONFIDENCE`, `UNKNOWN`), `depth_median_m`, `confidence` (`[0,1]`), `valid_pct`/`invalid_pct`, `valid_count`/`total_pixels` (absolute counts, added during the mp01_perception safety remediation because `valid_pct` alone is a lossy region-size-relative percentage not safely comparable across regions of different sizes).

`UNKNOWN` is a **hard gate**: any region with fewer valid disparity pixels than `RegionAnalyzer`'s `min_valid_pixels` threshold is unconditionally `UNKNOWN`, checked before any other signal (texture/entropy/confidence) — a region with zero stereo evidence can never be reported as any other class, including `CLEAR`. `SceneInterpreter` treats `UNKNOWN` as ambiguous; a region grid containing an `UNKNOWN` region directly ahead can never itself produce a `MOVE_FORWARD` navigation decision.

### `ObstacleAssessment`

`beams: List[BeamReading]` + `safest_beam: Optional[BeamReading]`. Each `BeamReading`: `index`, `x1`/`x2` (pixel column bounds), `distance_m` (`0.0` = no data), `status` (one of `ThreatAssessor.CLEAR`/`CAUTION`/`BLOCKED`/`NO_DATA`, plain strings not an enum — pre-existing, not changed in this pass). A beam with no valid depth but a high fraction of invalid (blocked) disparity pixels is reclassified `BLOCKED` rather than `NO_DATA` — catches textureless obstacles (e.g. a blank wall) that produce no stereo correspondence at all regardless of distance. Status changes are debounced (must persist `debounce_frames` consecutive calls) **except** when depth evidence disappears entirely (`evidence_lost`), which bypasses debounce immediately — a stale `CLEAR` must never keep being reported once the evidence behind it is gone.

## `PipelineHealth` (`models.PipelineHealth`)

Added in this recovery pass. `is_closed: bool`, `frames_processed: int`, `last_confidence: Optional[float]`, `last_processing_time_ms: Optional[float]` — the last two are `None` until `process()` has been called at least once since construction or the last `reset()`. Reports the pipeline's own lifecycle state, not a re-diagnosis of the scene.

## Coordinate frames

All image-space coordinates (`x1`/`x2` beam bounds, region grid pixel bounds) are in the **rectified left image's** pixel space — the frame everything downstream of `RectificationEngine.rectify()` operates in. `depth_map`/disparity values are per-pixel scalars, not associated with a 3D coordinate frame. `result.geometry` (Level 3, Phase E3) is camera-optical-frame X/Y/Z (`frames.FrameId.CAMERA_OPTICAL_LEFT` — OpenCV convention: X right, Y down, Z forward), metres. `result.geometry_body`/`obstacle_cloud`/`free_space_rays` (Level 3, Phases E4/E5) are body-frame (`frames.FrameId.BODY` — X forward, Y left, Z up, ROS REP-103), metres, produced by `geometry.transform_point_cloud()` applying `frames.RigidTransform`'s frozen convention (`p_out = rotation @ p_in + translation`) — see `docs/COORDINATE_FRAMES.md`. **This library performs no world-frame transform anywhere** — no localization, no map frame. That remains out of scope beyond E5.

## Geometry (Level 3, Phase E3) — frozen as of Phase E7 (2026-08-07)

Every contract below was validated end-to-end (synthetically and on real stereo hardware) and frozen in Phase E7 — no field, shape, unit, or invalid-value convention described below changed during that validation pass. See `docs/VALIDATION_REPORT.md`'s E7 addendum for the acceptance matrix and `docs/IMPLEMENTATION_STATUS.md`'s E7 addendum for what was actually run.

- **Gate:** `PipelineConfig.enable_geometry: bool`, default `False`. `False` reproduces pre-E3 behavior exactly — no `PointCloudBuilder` is even constructed, `result.geometry` is always `None`, zero added cost. `True` builds one `PointCloudBuilder` per pipeline instance (in `__init__`, reused across `process()` calls, same discipline as every other stage engine) and populates `result.geometry` every call.
- **Producer:** `geometry.PointCloudBuilder.build(raw_disparity)` — the one canonical point-cloud generator in this library (see `docs/LEVEL3_ARCHITECTURE.md`). Fed the pipeline's own `raw_disparity` (the same array `depth_map` was computed from); performs no independent disparity or depth recomputation.
- **Shape/units:** `result.geometry.points` is `(H, W, 3)` `float32`, metres, organized (pixel-aligned with `depth_map`/`disparity_map` — pixel `[v, u]` in `geometry.points` corresponds to the same pixel in `depth_map`). There is currently no unorganized (valid-points-only) output mode for the organized cloud itself — `geometry.PointCloud`'s frozen shape is inherently organized (unlike `ObstacleCloud`, which is unorganized by its own frozen contract — see below).
- **Invalid-point semantics:** `result.geometry.valid_mask` is `(H, W)` `bool`; wherever it is `False`, the corresponding `points[v, u]` is `(NaN, NaN, NaN)` — never `(0, 0, 0)` or any other silently-plausible value, since `(0, 0, 0)` is a legitimate point on the optical axis (see `geometry/types.py`'s module docstring). Empirically, `result.geometry.valid_mask` is identical to `result.valid_depth_mask` for the same frame (both derived from the same `raw_disparity`/`Q`/`MIN_DEPTH_M`/`MAX_DEPTH_M`) — see `tests/test_pipeline_geometry.py::TestGeometryEnabledOutput::test_valid_geometry_count_matches_valid_depth_mask_exactly`.
- **Timing:** not a separate field on `DepthPerceptionResult` (would require a new Tier 1 field beyond what this pass adds — see `docs/LEVEL3_PUBLIC_API.md`); logged at `DEBUG` level from `pipeline.py` on every call when geometry is enabled. The geometry stage's own cost is included in the existing `processing_time_ms` total like every other stage. See `docs/VALIDATION_REPORT.md` for measured overhead.

## Body-frame transform (Level 3, Phase E4)

- **Gate:** `DepthPerceptionPipeline(..., body_T_camera_left: Optional[frames.RigidTransform] = None)` — a new, additive, defaulted constructor parameter. `None` (the default) means "not calibrated" and is enforced, not just documented: `result.geometry_body` stays `None` even if `enable_geometry=True`. Validated at construction (fails fast, before any frame is processed) by reusing `calibration.contracts.RigCalibration.__post_init__`'s existing checks (`to_frame == FrameId.BODY`, `from_frame == FrameId.CAMERA_OPTICAL_LEFT`).
- **Producer:** `geometry.transform_point_cloud(cloud, transform)` (`geometry/rigid_transform.py`) — generic, not body-specific; applied here to `result.geometry` to produce `result.geometry_body`. Both coexist; `geometry` is never mutated or replaced.
- **Shape/units/invalid-point semantics:** identical to `result.geometry` above (same `(H, W, 3)` `float32` organized shape, same `NaN`-invalid convention, `valid_mask` copied unchanged — validity is frame-independent).

## Spatial evidence (Level 3, Phase E5)

Converts `result.geometry_body` into structured evidence, explicitly distinguishing three categories at every pixel:

| Category | Meaning | Where it shows up |
|---|---|---|
| **Observed surface / occupied evidence** | A valid measured 3D point | `result.obstacle_cloud.points` (subject to range/stride — see below) and every `free_space_rays` ray's endpoint (`origin + direction * range`) |
| **Observed free space** | The straight-line space between the sensor origin and a measured surface point | The half-open interval `[origin, endpoint)` each `free_space_rays` ray represents — the endpoint itself is surface, not free |
| **Unknown / unobserved space** | No valid measurement exists (invalid disparity, rejected depth, no stereo correspondence, occluded, outside FOV) | Everywhere `geometry_body.valid_mask` is `False` — produces **no** obstacle point and **no** ray; never inferred as free, never inferred as occupied |

**Core safety rule, enforced structurally, not by convention**: `build_obstacle_cloud`/`build_free_space_rays` both derive their point/ray selection directly from `cloud.valid_mask`, ANDed with (never inferred independently of) an `np.isfinite(...)` check on the computed distance/range — an invalid or non-finite-distance pixel can produce neither an obstacle point nor a ray, under any configuration. There is no code path that infers free space behind a measured surface, or from a missing measurement. Verified end-to-end through the real pipeline in `tests/test_pipeline_spatial_evidence.py::TestUnknownSpaceSafetyRule`.

- **Gates:** `PipelineConfig.enable_obstacle_geometry`/`enable_free_space_rays: bool`, both default `False`, independently toggleable. Neither has any effect unless `result.geometry_body` itself exists (`enable_geometry=True` **and** `body_T_camera_left` supplied) — E5 has nothing to derive evidence from otherwise, and never fabricates any.
- **`result.obstacle_cloud`** (`geometry.ObstacleCloud`, `geometry/obstacle_extractor.py`'s `build_obstacle_cloud`): unorganized `points: (N, 3) float32`, metres, `FrameId.BODY`, plus `distances_m: (N,) float32` (Euclidean distance from the camera's own origin — `body_T_camera_left.translation`, **not** the body coordinate origin `(0,0,0)`, per `ObstacleCloud.distances_m`'s own frozen docstring) and `confidence` if the source cloud carries one (currently always `None` in practice — nothing upstream populates it yet). Filtered by `PipelineConfig.obstacle_min_range_m`/`obstacle_max_range_m` (default `0.0`/`+inf` — no restriction beyond the sensor's own already-enforced `[DepthEstimator.MIN_DEPTH_M, MAX_DEPTH_M]` clamp) and `geometry_sampling_stride` (default `1`, a 2D grid decimation — `points[::stride, ::stride]` — not a count-based sample of the valid subset). Purely geometric: no semantic/object/floor/wall classification, no clustering.
- **`result.free_space_rays`** (`geometry.FreeSpaceRays`, `geometry/free_space.py`'s `build_free_space_rays`): `origins: (N, 3)` (every row identical — the single camera origin), `directions: (N, 3)` unit vectors, `ranges_m: (N,)`, all `float32`, `FrameId.BODY`. One ray per valid, non-degenerate (non-origin-coincident) point after `geometry_sampling_stride` decimation — **no** `obstacle_min_range_m`/`max_range_m` filtering applies here (those are obstacle-specific by name and by design; every real surface measurement, at any range the sensor already trusts, produces a ray). `endpoint = origin + direction * range_m` reconstructs the measured point exactly. No voxelization anywhere — **E5 does NOT produce an occupancy map**; these are single-frame observations suitable for a future occupancy consumer to integrate (E6+), not an integrated map themselves.
- **`result.geometry_metrics`** (`geometry.GeometryMetrics`, `geometry/geometry_metrics.py`'s `build_geometry_metrics`): populated whenever `geometry_body` exists, independent of the two flags above (cheap aggregation, no separate gate). Exactly 4 fields, each with one precise definition: `point_count` = `int(geometry_body.valid_mask.sum())`; `valid_fraction` = `point_count / geometry_body.valid_mask.size`; `min_obstacle_distance_m` = `min(obstacle_cloud.distances_m)` or `None` if `obstacle_cloud` wasn't computed or has zero points; `mean_free_space_m` = `mean(free_space_rays.ranges_m)` or `None` under the same two-cases-collapse-to-`None` rule.
- **Frozen-contract mismatches vs. this phase's task prose, resolved in favor of the frozen shape** (see `docs/LEVEL3_ARCHITECTURE.md`'s E5 update for the full account): no `timestamp` field on `ObstacleCloud`/`FreeSpaceRays` (the frame's timestamp remains available via `geometry_body.timestamp`); `FreeSpaceRays` uses `(origins, directions, ranges_m)`, not `(origin, endpoint)` pairs; `GeometryMetrics`' 4 fields are narrower than a fuller metric set could offer (no max/farthest distance, no separate obstacle/ray counts, no explicit unknown-fraction, no spatial coverage) — flagged as E6 candidates, not added.
- **Not yet implemented (E6+):** occupancy/voxel mapping, temporal fusion, vehicle envelope, collision-risk scoring, IMU. E5 alone does not complete Level 3 — see `docs/IMPLEMENTATION_STATUS.md` and `docs/E6_IMPLEMENTATION_PLAN.md`.

## Bounded temporal history (Level 4, Phase E2)

- **Gate:** `PipelineConfig.enable_temporal: bool`, default `False`. `False` reproduces pre-E2 behavior exactly — no `temporal.TemporalHistory` is constructed, `result.temporal_admission_status` is always `None`, zero added cost. `True` builds one `TemporalHistory` per pipeline instance (in `__init__`, reused across `process()` calls), admits one record per frame, and populates `result.temporal_admission_status` every call.
- **Producer:** `DepthPerceptionPipeline.process()` constructs a `temporal.TemporalRecord` from values already computed that call (`result_timestamp`, `traversability`-derived `confidence`, `classify_geometry_quality()`'s verdict if `geometry_metrics` exists, and the `motion_hint` parameter) and calls `temporal.TemporalHistory.admit()` exactly once. No independent recomputation of any Level 3 value.
- **Bounding:** two independent bounds, tighter wins — `PipelineConfig.temporal_max_records` (default `30`, a hard count cap) and `PipelineConfig.temporal_max_age_s` (default `1.0`, timestamp-based, never wall-clock). `PipelineConfig.temporal_gap_limit_s` (default `0.5`) governs a separate concept: a gap between two consecutively *accepted* timestamps larger than this clears old history and starts a fresh sequence, rather than bridging it.
- **Chronology outcomes:** `result.temporal_admission_status` is one of `temporal.TemporalAdmissionStatus.ACCEPTED`/`ACCEPTED_NEW_SEQUENCE`/`REJECTED_INVALID_TIMESTAMP`/`REJECTED_OLDER_TIMESTAMP`/`REJECTED_DUPLICATE_TIMESTAMP`. A rejection never affects any other field on the same `DepthPerceptionResult` — every Level 3 value (`disparity_map` through `geometry_metrics`) is computed identically regardless of whether this frame's timestamp was admitted to history.
- **`temporal.TemporalRecord` fields:** `timestamp` (chronology key), `confidence` (Level 0-2's `DepthPerceptionResult.confidence`, always present regardless of whether geometry is enabled), `geometry_quality` (one of `geometry.GeometryQuality`'s three values via `classify_geometry_quality()`, or `None` if `geometry_metrics` wasn't computed this call), `motion_hint` (the frame's associated `temporal.MotionHint`, or `None`). No disparity/depth array, mask, or point cloud of any kind is ever retained — see `docs/E2_TEMPORAL_HISTORY_PLAN.md`'s memory-decision table.
- **`StereoObservation.motion_hint`:** reserved/unconsumed at Level 4 E1; as of E2, `process_observation()` forwards it into `process()`'s new `motion_hint` parameter, which associates it with the frame's `TemporalRecord` — still pure bookkeeping, no integration/alignment/algorithm reads its contents.
- **Reset:** `DepthPerceptionPipeline.reset()` now also clears temporal history (when enabled) in addition to its pre-existing `ThreatAssessor` state reset — the next frame after `reset()` starts a fresh temporal sequence with zero historical influence.
- **Not yet implemented (E3+):** temporal filtering, temporal fusion, IMU integration, rotational compensation, persistence classification, any comparison of one `TemporalRecord` against another. E2 is chronology/bookkeeping infrastructure only — see `docs/E2_TEMPORAL_HISTORY_PLAN.md` and `docs/E3_IMPLEMENTATION_PLAN.md`.

*(E3's `temporal.TemporalConsistency`, E4's `temporal.TemporalStabilization`, E5's `temporal.RotationCompensationStatus`, and E6's `temporal.MotionAwareReliability` each followed the same "additive `DepthPerceptionResult` field, gated by its own `PipelineConfig` flag(s), computed from already-existing values, zero regression on earlier output" pattern established above — see `docs/E3_IMPLEMENTATION_PLAN.md`, `docs/E4_IMPLEMENTATION_PLAN.md`, `docs/LEVEL4_E5_IMPLEMENTATION_PLAN.md`, `docs/LEVEL4_E6_IMPLEMENTATION_PLAN.md`, and `docs/LEVEL4_CONTRACTS.md`'s own per-contract table for their full data contracts; not independently re-tabulated in this document.)*

## Per-cell temporal persistence (Level 4, Phase E7)

- **Gate:** `PipelineConfig.enable_temporal_persistence: bool`, default `False`, effective only when `enable_temporal` **and** `enable_motion_aware_reliability` are also `True` (E7 hard-requires E6's own reliability verdict as an input — see below). `False`/unmet prerequisites reproduce pre-E7 behavior exactly: no `temporal.persistence.TemporalPersistenceTracker` is constructed, `result.temporal_persistence` is always `None`, zero added cost.
- **Producer:** `temporal.persistence.TemporalPersistenceTracker.update()`, called once per frame by `DepthPerceptionPipeline.process()`, after E6's own reliability stage, from values already computed that call (`depth_snapshot_m`, `result_timestamp`, `motion_aware_reliability.state`, `motion_hints`) — no independent recomputation of any Level 0-6 value.
- **Spatial evidence categories, extended into time:** the same three-way distinction `DATA_CONTRACTS.md`'s spatial-evidence table already enforces per frame (observed surface / observed free space / unknown) is extended, per cell of the decimated grid, into four temporal codes on `result.temporal_persistence.state_grid` (`temporal.persistence.TemporalPersistenceCellState`): `NO_EVIDENCE` (0 — no current occupied evidence, no tracked history; never means "free"), `NEW` (1 — occupied this frame, insufficient repeated support yet), `PERSISTENT` (2 — occupied, or absent within a tolerated grace window, with support count at/above `PipelineConfig.persistence_min_support_count`), `DISAPPEARING` (3 — absent beyond the grace window, not yet expired). There is no fifth code meaning FREE — an expired or long-absent cell reverts to `NO_EVIDENCE`, never to a fabricated "known clear" value. See `docs/LEVEL4_E7_IMPLEMENTATION_PLAN.md` section 6.
- **`result.temporal_persistence`** (`temporal.TemporalPersistence`): `state` (`temporal.persistence.TemporalPersistenceState.CLASSIFIED`/`UNRELIABLE`/`INSUFFICIENT_EVIDENCE` — the frame-level gate outcome), `state_grid`/`support_count_grid`/`age_s_grid` (three `(H_dec, W_dec)` arrays, `None` together whenever nothing has been classified yet), `new_count`/`persistent_count`/`disappearing_count`/`expired_count` (always-defined non-negative integers), `eligible_count` (denominator, `NO_EVIDENCE` cells excluded), `persistent_fraction` (`None`, never 0/0, when `eligible_count == 0`).
- **Reliability gate (Rule 7):** whenever this frame's own `result.motion_aware_reliability.state == MotionAwareReliabilityState.UNRELIABLE`, the tracker performs no update at all this call — no support increment, no new classification, no contradiction-reset — and instead re-exposes its own unchanged snapshot from the most recent `CLASSIFIED` frame (`state = UNRELIABLE`). An unreliable frame can neither create nor reinforce persistence, and does not erase it either.
- **Rotation compensation:** when `PipelineConfig.enable_rotation_compensation` is `True` and admissible `MotionHint` samples exist for the interval, the tracker's own per-cell state (tracked depth, support count, absence streak, first-observed timestamp) is re-expressed in the current frame's grid via `temporal.rotation_compensation.compensate_prior_geometry_with_payload()` — the exact same reprojection E5 already uses for `TemporalRecord.depth_snapshot_m`, extended additively to carry the tracker's own auxiliary channels through the identical mapping, never a second, independent motion-compensation implementation.
- **Reset/gap:** `DepthPerceptionPipeline.reset()` and a `temporal.TemporalAdmissionStatus.ACCEPTED_NEW_SEQUENCE` gap-restart both clear the persistence tracker completely (mirrors `TemporalHistory.clear()`'s own "complete amnesia" contract) — the next frame after either event starts a brand-new persistence sequence with zero historical influence.
- **Bounded memory:** four fixed-size `(H_dec, W_dec)` arrays, shape fixed on first `update()` call and never resized thereafter — no growth with frame count, no `TemporalRecord`/`DepthPerceptionResult` ever retained by the tracker. See `docs/LEVEL4_E7_IMPLEMENTATION_PLAN.md` section 9.

Real-hardware validation remains explicitly pending — see `docs/LEVEL4_HARDWARE_VALIDATION_PENDING.md` — and does not block the software freeze.

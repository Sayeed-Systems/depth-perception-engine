**LEVEL 4 E7 — DETERMINISTIC, PER-CELL TEMPORAL-PERSISTENCE CLASSIFICATION IMPLEMENTED.**
**NO SEMANTICS. NO NEURAL/LEARNED INFERENCE. NO OBJECT RECOGNITION. NO PLANNING. NO TRAJECTORY PREDICTION. NO VIO/SLAM/LOCALIZATION.**

Objective (as specified): classify geometric evidence across time as NEW / PERSISTENT / DISAPPEARING / INSUFFICIENT_EVIDENCE / UNRELIABLE — persistence requires *repeated* chronological support from E2-E6, one observation can never become PERSISTENT, strong current geometry must always appear immediately as NEW, a single dropout must not instantly erase persistence, historical evidence must expire deterministically, UNKNOWN must never become FREE, and E6-UNRELIABLE observations must never create or reinforce persistence.

## 1. Exact persistence definition

**Persistence, precisely:** a decimated grid cell (the same `(H_dec, W_dec)` grid `TemporalRecord.depth_snapshot_m`/E3/E4 already use — `PipelineConfig.temporal_consistency_sampling_stride`, no new grid invented) is PERSISTENT when its own **support count** — the number of consecutive, chronologically-agreeing occupied observations, tracked per cell — has reached `PipelineConfig.persistence_min_support_count` (>= 2, enforced at construction). "Agreeing" reuses E3's own exact tolerance (`PipelineConfig.temporal_consistency_agreement_tolerance_m`) applied between the current frame's decimated depth and the tracker's own per-cell tracked depth (itself the most recent agreeing observation's value, rotation-compensated into the current frame's grid when E5 is enabled — section 5 below). A cell is never PERSISTENT from a single observation, structurally: support starts at 1 (NEW) and the minimum legal threshold is 2.

## 2. States

Two disjoint state surfaces, each precisely defined, together covering the five states named:

- **Per-cell** (`temporal.persistence.TemporalPersistenceCellState`, `TemporalPersistence.state_grid`, one int8 code per grid cell): `NO_EVIDENCE` (0, background — no current evidence, no tracked history; the overwhelming majority of cells in any real scene), `NEW` (1), `PERSISTENT` (2), `DISAPPEARING` (3).
- **Frame-level gate** (`temporal.persistence.TemporalPersistenceState`, `TemporalPersistence.state`): `CLASSIFIED` (this frame's own evidence updated the tracker), `UNRELIABLE` (E6 said UNRELIABLE this frame — Rule 7, section 6 below — tracker frozen, not updated, existing grid re-exposed unchanged), `INSUFFICIENT_EVIDENCE` (a genuine structural incompatibility between this frame's grid shape and the tracker's own accumulated shape — mirrors `TemporalConsistencyState.NOT_COMPARABLE`'s own rare, defensive trigger; unreachable in ordinary single-pipeline-instance operation, since the decimated grid shape never changes within one pipeline instance).

This is a deliberate design choice, not an accident of implementation: persistence is inherently *spatial* (one region of a frame can be freshly NEW while another is long PERSISTENT and a third is DISAPPEARING, all in the same call — a single frame-level string cannot represent that), whereas "was this frame's own evidence trustworthy enough to use at all" is inherently a *frame-level* gate (matching E3/E4/E6's own precedent of one `state` string per call). Splitting the five named states across these two surfaces is the minimal representation that is precise for both questions.

## 3. Support/age thresholds

Three new `PipelineConfig` fields, all validated in `__post_init__`, same "policy choice, not a physical constant" discipline as every prior threshold in this file:

- **`persistence_min_support_count: int = 2`** (validated `>= 2` — a *hard architectural rule*, not a tunable policy default that happens to default to 2: Rule 2 forbids a single observation from ever reading PERSISTENT, and 2 is the smallest value for which that is even possible to satisfy while still allowing persistence to exist at all).
- **`persistence_max_dropout_frames: int = 1`** (validated `>= 0`). The grace window: a previously-PERSISTENT cell tolerates this many consecutive absent frames (current decimated depth `<= 0.0`) before reading DISAPPEARING instead of PERSISTENT — Rule 4's "one dropout must not instantly erase."
- **`persistence_expiration_absence_frames: int = 5`** (validated `> persistence_max_dropout_frames`). The absence count beyond which a cell's tracked state is fully, deterministically cleared — support count reset to 0, tracked depth/first-observed-timestamp reset to 0.0, state reverts to `NO_EVIDENCE` (never a fabricated FREE) — Rule 5.

**Age**, where meaningful (`TemporalPersistence.age_s_grid`, per cell, float32 seconds): `current_timestamp - first_observed_timestamp`, where `first_observed_timestamp` is the timestamp of the cell's own most recent *fresh* start (a `NEW` classification — either a genuinely first observation or a reset following a contradiction) — not the cell's very first-ever observation across all time, since a contradiction legitimately represents a *different* physical surface appearing at that pixel location, and its own age must start over. `0.0` for an untracked cell and, not coincidentally, also `0.0` for a cell classified `NEW` this exact frame — both correctly represent "zero elapsed support time." Age is recomputed fresh even on an `UNRELIABLE` frame (elapsed real time does not require reinforcement to be true), but never on an `INSUFFICIENT_EVIDENCE` frame (no grid exists to compute it against).

## 4. History selection

**No second history buffer.** E7 does not scan `temporal.TemporalHistory`'s own retained records at all — it does not need N historical `TemporalRecord`s to judge persistence, only its own tracker's per-cell running state (support count, tracked depth, absence streak, first-observed timestamp — four `(H_dec, W_dec)` arrays, fixed size, never storing a `TemporalRecord` or `DepthPerceptionResult`). This directly satisfies the instruction "reuse the existing bounded history... do not create another unbounded tracker" two ways at once: E2's `TemporalHistory` remains the sole chronology-admission buffer (E7 never duplicates its job), and E7's own tracker is bounded by construction (fixed array shape, no growth with frame count — proven by `tests/test_temporal_persistence.py::TestBoundedMemory`/`TestPipelineBoundedMemory`), not merely bounded by a cap that could still be described as "another tracker" in spirit.

The tracker's "history" is exactly one prior state per cell — the most recent agreeing observation — carried forward every frame, exactly the same "single most recent comparable prior" selection discipline E3/E4 already use (`docs/E3_IMPLEMENTATION_PLAN.md`'s own Decision 2), extended into a per-cell *running* value rather than one whole-frame `TemporalRecord`.

## 5. Interaction with E3-E6

- **E2 (bounded history):** E7 reuses E2's own chronology-admission discipline indirectly — a gap-triggered new sequence (`TemporalAdmissionStatus.ACCEPTED_NEW_SEQUENCE`) clears the persistence tracker too (`DepthPerceptionPipeline.process()`, immediately after `admit()`), matching `TemporalHistory`'s own "complete amnesia" behavior on a discontinuity (`docs/E2_TEMPORAL_HISTORY_PLAN.md`'s Decision 3/7) rather than incorrectly carrying pre-gap support counts into an unrelated new sequence. E7 never reads `TemporalHistory.records` directly (section 4).
- **E3 (temporal consistency):** E7 reuses E3's own agreement tolerance (`PipelineConfig.temporal_consistency_agreement_tolerance_m`) as its own per-cell "agrees" definition — one shared definition of "agree," never a second, independent tolerance concept. E7 does **not** reuse E3's aggregate `agreement_fraction`/`comparable_count` (those are frame-level scalars over the *previous frame's* comparison; E7 needs a *per-cell* boolean derived from its own multi-frame tracked state, a genuinely different question E3 does not answer).
- **E4 (stabilization):** E7 does not consume `TemporalStabilization` at all — E4 answers "what is the best current depth estimate," a different question from "has this cell been repeatedly observed." E7's own `tracked_depth` is a simpler, independent running estimate (last-agreeing-value, not a confidence-weighted blend) — this is a deliberate non-dependency, not an oversight: chaining E7 onto E4's own already-blended output would make persistence support depend on E4's blending weights, an indirection this phase's own "geometric only, one precise meaning per field" discipline argues against.
- **E5 (rotation compensation):** reused directly and exclusively — no second motion-compensation implementation. `temporal/rotation_compensation.py` gained one additive sibling function, `compensate_prior_geometry_with_payload()`, sharing `compensate_prior_geometry()`'s own exact reprojection math (both now call a shared private helper, `_reproject_source_to_target()` — a pure refactor, proven byte-identical by the pre-existing, unmodified E5 test suite: `tests/test_rotation_compensation.py` passes unchanged). E7's tracker calls this new function once per frame (only when it has any tracked cells, `PipelineConfig.enable_rotation_compensation` is `True`, and at least one admissible `MotionHint` sample exists for the interval — the exact same `select_motion_hint_samples()`/`integrate_angular_velocity()` E5 itself uses) to co-warp its own `tracked_depth`/`support_count`/`absence_streak`/`first_observed_timestamp` arrays through the identical rotation-compensated mapping the depth channel uses, so a physically stationary surface stays spatially tracked across a rotating sensor — proven by `tests/test_temporal_persistence.py::TestRotationCompensatedPersistence`, which shows a synthetically-rotated surface reaches PERSISTENT with compensation enabled and does not (or far less) without it.
- **E6 (reliability):** the direct, hard gate. `TemporalPersistenceTracker.update()` receives this frame's own `MotionAwareReliability.state` and, when it is `UNRELIABLE`, skips every per-cell update entirely (Rule 7) — no support increment, no new `NEW` classification, no contradiction-reset — returning the tracker's *own unchanged* snapshot from the most recent `CLASSIFIED` frame instead (state `UNRELIABLE`), so an unreliable frame neither creates nor reinforces persistence, and also does not erase it (matching Rule 4's spirit for degraded reliability, not just ordinary dropout). Every other E6 state (`RELIABLE`, `DEGRADED`, `INSUFFICIENT_EVIDENCE`, and `None` when E6 itself is disabled — impossible in practice since E7 hard-requires E6 enabled, section 7) permits a normal update; `DEGRADED` and `INSUFFICIENT_EVIDENCE` are *not* additionally penalized (E6 already expresses "how much to trust this," E7 does not invent a second, redundant discount on top).

## 6. UNKNOWN != FREE

Structural, not incidental: `TemporalPersistenceCellState` has exactly four codes, and none of them means or implies FREE space. `NO_EVIDENCE` (the background default, and the value every expired cell reverts to) means only "nothing to report here" — never "this is clear." A dropout cell within its grace window stays `PERSISTENT` (still reporting the *last known occupied* evidence, honestly aged); once past expiration it reverts to `NO_EVIDENCE`, not to any "free" value — the tracker never writes a value meaning "this is now known-clear" anywhere. Verified structurally by `tests/test_temporal_persistence.py::TestUnknownNeverFree`.

## 7. Output contract

`DepthPerceptionResult.temporal_persistence: Optional[temporal.TemporalPersistence] = None`, appended last (after `motion_aware_reliability`), additive — every existing field byte-identical whether or not this one is populated (`tests/test_temporal_persistence.py::TestPipelineOutputsUnchanged`). `None` unless **all three** of `PipelineConfig.enable_temporal`, `enable_motion_aware_reliability`, and `enable_temporal_persistence` are `True` — E7 hard-requires E6 (section 5's reliability gate cannot function without a real `MotionAwareReliability.state` to read), unlike E4/E5's mutual independence from each other. `temporal.TemporalPersistence` itself (`temporal/types.py`) carries: `state`, `state_grid`, `support_count_grid`, `age_s_grid` (all three arrays `None` together whenever `state != CLASSIFIED and state != UNRELIABLE-with-prior-history`, i.e. whenever there is nothing to expose yet), `new_count`/`persistent_count`/`disappearing_count`/`expired_count` (always-defined non-negative integers, 0 when nothing to report), `eligible_count` (`new_count + persistent_count + disappearing_count` — `NO_EVIDENCE` cells excluded, matching every other `*_fraction` denominator convention in this library), `persistent_fraction` (`None`, never 0/0, when `eligible_count == 0`).

## 8. Reset / gap / degradation behavior

- **`reset()`:** `DepthPerceptionPipeline.reset()` now also calls `TemporalPersistenceTracker.clear()` when enabled — every array is discarded; the next `update()` call re-derives grid shape and starts a brand-new sequence from zero, exactly mirroring `TemporalHistory.clear()`'s own "complete amnesia" contract. Proven by `tests/test_temporal_persistence.py::TestResetClearsState`/`TestPipelineClassifiesRepeatedEvidence::test_reset_clears_pipeline_level_persistence`.
- **Gap (`ACCEPTED_NEW_SEQUENCE`):** the pipeline clears the persistence tracker in the same branch that already handles `TemporalHistory`'s own gap-triggered wipe — a large timestamp discontinuity starts a fresh persistence sequence too, not just a fresh chronology. Proven by `test_large_timestamp_gap_starts_fresh_sequence`.
- **Degradation (E6 `UNRELIABLE`):** frozen, not erased (section 5/6) — proven by `TestReliabilityGating`.
- **Missing timestamp:** if `result_timestamp` is `None` this call, E7 is not evaluated at all this frame (`temporal_persistence` stays `None` for that call only) — mirrors `TemporalHistory.admit()`'s own `REJECTED_INVALID_TIMESTAMP` outcome; no chronology can be established without a real timestamp, so persistence is simply not judged rather than guessed.
- **Structural incompatibility:** `INSUFFICIENT_EVIDENCE` (section 2), unreachable in ordinary operation, defensive only.

## 9. Memory/latency impact

**Memory:** four fixed-size `(H_dec, W_dec)` arrays (`float32`, `int32`, `int32`, `float64`) — for the project's own default `temporal_consistency_sampling_stride=4` decimation, comparable in size to a single `TemporalRecord.depth_snapshot_m`, i.e. a small, constant, one-time allocation independent of frame count. No growth ever — proven directly (`TestBoundedMemory`/`TestPipelineBoundedMemory`).

**Latency:** one elementwise-vectorized NumPy pass per frame over the decimated grid (boolean masks, comparisons, `np.where`) — no per-pixel Python loop (mirrors `compensate_prior_geometry()`'s own "fully vectorized" discipline). When rotation compensation is exercised, one additional call to `compensate_prior_geometry_with_payload()` (itself the same cost class as E5's own `compensate_prior_geometry()`, plus a small, fixed 3-channel payload loop — bounded by channel COUNT, never by pixel count, same "loop bounded by count not pixels" precedent `integrate_angular_velocity()`'s own sample loop already established). Logged separately at `DEBUG` level (`"Temporal persistence stage: %.2f ms"`, matching every other per-stage log line) while still included in `processing_time_ms`'s total, matching every prior phase's convention.

## 10. What this phase explicitly did not do

Store a `TemporalRecord` or `DepthPerceptionResult` anywhere in the tracker. Create a second, competing history buffer alongside `temporal.TemporalHistory`. Implement a second, independent motion-compensation/reprojection algorithm (`compensate_prior_geometry_with_payload()` reuses `compensate_prior_geometry()`'s own exact math via a shared private helper). Modify `temporal/consistency.py`, `temporal/stabilization.py`, or `temporal/reliability.py`. Modify `compensate_prior_geometry()`'s own pre-E7 behavior (proven: the full, unmodified E5 test suite still passes). Modify any Level 0-3 algorithm. Fabricate FREE space anywhere. Add semantics, neural/learned inference, object recognition, planning, trajectory prediction, VIO, SLAM, or localization. Modify `mp01_perception`, `mp01_localization`, `state_estimation_engine`, `mp01_mapping`, or any other repository. Commit or push. Modify or delete the pre-existing, unrelated `docs/E7_IMPLEMENTATION_PLAN.md` (Level 3's own stale planning stub). Implement E8.

## Readiness assessment

E7 required one genuinely new engineering decision beyond straightforward reuse: how to keep a small amount of *cross-frame, per-cell* bookkeeping spatially valid under camera rotation without writing a second reprojection implementation. Resolved by extending E5's own module additively (a shared, refactored, tested projection-index helper) rather than either (a) reimplementing reprojection inside `temporal/persistence.py`, or (b) skipping rotation-awareness for persistence entirely. Every other design question resolved to direct reuse of an already-frozen E2-E6 contract. Unresolved E8 decisions are listed in `docs/LEVEL4_E8_IMPLEMENTATION_PLAN.md`.

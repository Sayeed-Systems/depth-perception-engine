> **Addendum (2026-08-08, Level 4 Phase E2 — BOUNDED TEMPORAL HISTORY):** the twelve E1-open design questions were resolved by explicit project-architect decision (`docs/E2_TEMPORAL_HISTORY_PLAN.md` records each one) and implemented. **No temporal filtering, temporal fusion, IMU integration, rotational compensation, or persistence classification was implemented** — E2 is chronology/bookkeeping infrastructure only.

> **`temporal.TemporalHistory`** (`temporal/history.py`) is a bounded, deterministic chronology component: two independent eviction bounds (`PipelineConfig.temporal_max_records=30`, `PipelineConfig.temporal_max_age_s=1.0`s, tighter wins, both enforced only after a new valid observation is appended — a full buffer never rejects a chronologically-valid newest observation) plus discontinuity detection (`PipelineConfig.temporal_gap_limit_s=0.5`s — a gap larger than this clears old history and starts a fresh sequence, reported via the distinct `TemporalAdmissionStatus.ACCEPTED_NEW_SEQUENCE` status rather than silently folded into plain `ACCEPTED`). Age-based eviction is computed purely from `TemporalRecord.timestamp` values — `temporal/history.py` never imports the `time` module, proven structurally by `tests/test_temporal_history.py::TestTimeBound::test_history_module_never_imports_time`, not just asserted. Older/duplicate/out-of-order timestamps are rejected without mutating existing history (`TemporalAdmissionStatus.REJECTED_OLDER_TIMESTAMP`/`REJECTED_DUPLICATE_TIMESTAMP`; an out-of-order arrival is handled by the identical older-timestamp path, since it *is* one once any record exists — no separate fault counter was added, since none was frozen at E1).

> **Addendum (2026-08-08, Level 4 Phase E3 — READ-ONLY TEMPORAL CONSISTENCY):** the five E2-open design questions were resolved by explicit project-architect decision (`docs/E3_IMPLEMENTATION_PLAN.md` records each one) and implemented. **No temporal smoothing, fusion, IMU integration, rotational compensation, persistence classification, VIO, SLAM, or localization was implemented** — E3 is a read-only comparison, never a modification, of current vs. one prior frame's evidence.
>
> **`temporal.compute_temporal_consistency()`** (`temporal/consistency.py`) compares the current frame's `depth_map` against the single most recent comparable prior `temporal.TemporalRecord`'s retained snapshot — never a multi-frame blend or window. Substrate chosen deliberately: `depth_map`, not `geometry`/`geometry_body`, because it is the one per-pixel evidence guaranteed present regardless of `PipelineConfig.enable_geometry` — the same "usable from stereo alone" argument E2 used for `confidence`. Exact math: `comparable_count` = pixels valid (`> 0.0`) in both snapshots; `agreeing_count` = comparable pixels within `PipelineConfig.temporal_consistency_agreement_tolerance_m=0.05`m; `disagreement_count = comparable_count - agreeing_count`; `agreement_fraction = agreeing_count / comparable_count` **only when `comparable_count > 0`** — the "score=0 ambiguity" the architect explicitly warned about is resolved by short-circuiting `comparable_count == 0` to `INSUFFICIENT_EVIDENCE` with `agreement_fraction=None` before any fraction is computed, so "no evidence" and "full contradiction" (`CONTRADICTORY`, a real low `agreement_fraction`) are never conflated. Four states — `temporal.TemporalConsistencyState.CONSISTENT`/`CONTRADICTORY`/`INSUFFICIENT_EVIDENCE`/`NOT_COMPARABLE` — audited against `GeometryQuality`/`TemporalAdmissionStatus` first; neither matched this semantics, so a new plain-string-constants class was warranted, not a repurposing.
>
> **Trigger, implemented as one uniform rule, not scattered special cases:** `DepthPerceptionPipeline.process()` captures `previous_latest = self._temporal_history.latest` *before* calling `TemporalHistory.admit()` (admission mutates the buffer), then computes `previous_for_comparison = previous_latest if admission_status == ACCEPTED else None`. This single line correctly produces every case the architect's trigger table named: first frame ever / first after `reset()` (`previous_latest` already `None`) → `INSUFFICIENT_EVIDENCE`; gap-triggered new sequence (`ACCEPTED_NEW_SEQUENCE`, `previous_for_comparison` forced `None` — the pre-gap record must never leak across the discontinuity, per E2's own Decision 7) → `INSUFFICIENT_EVIDENCE`; chronology-rejected frame (`REJECTED_*`) → `temporal_consistency` stays `None` entirely, no comparison attempted (avoids a second status field answering the same question `temporal_admission_status` already answers); ordinary continuous frame with real prior history → a real comparison. Missing `MotionHint` never blocks this — `compute_temporal_consistency()` doesn't accept or read one.
>
> **`temporal.TemporalRecord` extended** (Decision 5, only after confirming the E2-frozen 4 fields genuinely could not support geometric comparison): `depth_snapshot_m: Optional[np.ndarray] = None`, `depth_map[::stride, ::stride]` at `PipelineConfig.temporal_consistency_sampling_stride=4` (a new, independent knob — not `geometry_sampling_stride`, which decimates a `PointCloud` for a different, E5 purpose), reusing `depth_map`'s own `0.0`-is-invalid convention exactly (one array, not two — no second validity mask needed). Memory cost computed, not guessed: at the project's own 320×240 real-hardware calibration and default stride, one snapshot ≈ 19.2 KB; at `temporal_max_records=30`, worst case ≈ 576 KB — small next to a single full-resolution `depth_map` (307 KB), and only the single newest record is ever actually read for comparison (every other buffered record's snapshot is inert, an accepted trade-off of extending the existing bounded-buffer model rather than inventing a separate single-slot cache the architect didn't ask for).
>
> **Safety enforcement (Decision 4), structural not just behavioral:** `compute_temporal_consistency()` is a pure function — two small arrays in, one small immutable value out, no mutable reference to any Level 3 type in its signature (verified in `tests/test_temporal_consistency.py::TestCurrentEvidenceUnchanged::test_compute_temporal_consistency_receives_no_mutable_level3_reference`) — so it cannot rewrite depth, geometry, or obstacles, promote `UNKNOWN` to `FREE`, or average historical geometry into current geometry, under any outcome. Proven behaviorally too: `test_contradictory_verdict_does_not_alter_any_level3_field` forces a real `CONTRADICTORY` verdict through the actual pipeline (by directly admitting a synthetic, deliberately-far-off prior record via the already-exposed `.temporal_history` property, then processing the real frame again) and shows `disparity_map`/`depth_map`/masks/`confidence`/`traversability_mask.decision` are byte-identical to an `enable_temporal=False` pipeline processing the identical frame sequence.
>
> **"No invented alignment" rule, implemented within what this library can actually know:** since a single `DepthPerceptionPipeline` instance has one fixed calibration/resolution for its lifetime, any two of its own frames already share the same rectified pixel grid — pixel-indexed comparison is always in the same image domain. This library has no pose/motion-estimation capability and therefore no way to *detect* camera motion between frames, only to *observe its consequence* (the same pixel now reporting a materially different depth) — which `CONTRADICTORY` already reports honestly. `NOT_COMPARABLE` is reserved for the one genuinely checkable structural incompatibility: a shape mismatch between the current and stored snapshots.
>

> **Addendum (2026-08-08, Level 4 Phase E4 — DETERMINISTIC, CONFIDENCE-AWARE TEMPORAL STABILIZATION):** the ten E4 architect decisions were resolved and implemented, recorded in full in `docs/E4_IMPLEMENTATION_PLAN.md`. **No IMU integration, motion warping, ego-motion estimation, rotation/translation compensation, neural network, learned weighting, or opaque blended score of any kind was implemented** — E4 is one closed-form, deterministic, bounded weighted average, additive alongside (never a replacement of) the raw current observation.

> **`temporal.compute_temporal_stabilization()`** (`temporal/stabilization.py`) blends the current frame's decimated depth snapshot with the single most recent comparable prior `TemporalRecord`'s own snapshot (Phase E3's `depth_snapshot_m`, reused as-is — no new retained history). A frame-level gate (all four conditions AND-ed) must pass before any blending is attempted: E3's `temporal_consistency.state` must be `CONSISTENT` or `CONTRADICTORY` (both mean "comparable," as opposed to `NOT_COMPARABLE`); `comparable_count / current_snapshot.size >= PipelineConfig.temporal_stabilization_min_comparable_fraction` (default `0.1`); `previous_record.confidence >= PipelineConfig.temporal_stabilization_min_history_confidence` (default `0.3`, reusing Level 0-2's own already-defined confidence scalar — no new "temporal trust" concept). >
> **Per-pixel safety, not aggregate-level:** even within an aggregate-`CONTRADICTORY` frame, each pixel is judged independently using the exact same tolerance E3 already uses (`temporal_consistency_agreement_tolerance_m` — one definition of "agree," never duplicated). A pixel current doesn't see (`current_valid=False`) is never filled from history — structurally, not by policy exception, satisfying "UNKNOWN never becomes FREE from history." A pixel where current and a valid prior disagree beyond tolerance keeps its current value unchanged — "strong current contradictory geometry always wins," implemented as a structural no-op on that pixel, not a special case. Only pixels where both are valid *and* agree get a genuine blend: `stabilized = (current + w * previous) / (1 + w)` where `w = previous_record.confidence` — current's own weight fixed at `1.0`, so history can never numerically outweigh or dominate current (bounded to at most a 50/50 split). Every weight and threshold has exactly one documented meaning (Decision 4's explicit requirement); no arbitrary "AI confidence" anywhere.
>
> **`TemporalRecord` was NOT extended** — Decision 5 confirmed this mathematically: `depth_snapshot_m` (E3) and `confidence` (E2) already carry everything the estimator needs. Memory cost of this phase: zero additional bytes retained in `TemporalHistory`'s bounded buffer; the one new array (`temporal_stabilization.stabilized_depth_m`) lives only on the per-call `DepthPerceptionResult`, same lifetime as `depth_map`, never cached or buffered.
>
> **Output contract:** `DepthPerceptionResult.temporal_stabilization: Optional[temporal.TemporalStabilization] = None`, appended last, additive. New dataclass with `state` (`STABILIZED`/`CURRENT_ONLY_FALLBACK`/`INSUFFICIENT_EVIDENCE`) plus explicit `eligible_count`/`stabilized_count`/`contradiction_count`/`stabilized_fraction`/`contradiction_fraction` — `contradiction_fraction` is tracked as its own metric specifically because an aggregate `STABILIZED` frame can still have individually-overridden pixels that `state` alone cannot represent. Gated by a new `PipelineConfig.enable_temporal_stabilization: bool = False`, nested underneath `enable_temporal` (mirrors `enable_obstacle_geometry`/`enable_free_space_rays`'s own precedent of an opt-in flag under a broader one) — has no effect unless `enable_temporal` is also `True`.
>
> **Failure/recovery satisfied by construction**, matching this repository's established discipline (Level 3's own stages are also not wrapped in `try/except` — a genuine bug should surface, not be silently swallowed): missing history, invalid prior geometry, timestamp discontinuity, missing `MotionHint`, and non-comparable observations all collapse to the same `INSUFFICIENT_EVIDENCE` gate-failure path, none of which can raise. Recovery is automatic because there is no persistent E4-specific state — every `process()` call re-evaluates the gate fresh.

> **Addendum (2026-08-08, Level 4 Phase E5 — ROTATIONAL MOTION COMPENSATION):** the ten E5 architect decisions were resolved and implemented, recorded in full in `docs/LEVEL4_E5_IMPLEMENTATION_PLAN.md` (a disambiguated filename — `docs/E5_IMPLEMENTATION_PLAN.md` already existed as a stale, unrelated **Level 3** planning stub for its own independently-numbered Phase E5 (`ObstacleCloud`/`FreeSpaceRays`/`GeometryMetrics`, already implemented via a different path); that file was left untouched, not overwritten — a naming collision between the two levels' independent phase counters, not an architectural contradiction, flagged for a future pass to resolve if desired). **No IMU bias estimation, accumulated orientation, translation compensation, VIO, SLAM, localization, world-frame output, or neural/learned component was implemented** — E5 computes only an ephemeral relative rotation, used once per `process()` call and discarded.

> **`temporal.rotation_compensation`** integrates a chronologically-ordered, already-filtered sequence of `MotionHint` samples on SO(3): `ΔR_k = Exp([ω_k]_x · Δt_k)` via `cv2.Rodrigues` (reusing this project's existing OpenCV dependency, not hand-rolled small-angle math), composed by post-multiplication (`ΔR_total = ΔR_1 @ ... @ ΔR_n` — the standard "compose in the local/body frame" rule, correct for gyro-reported angular velocity). The quantity actually used, `ΔR_prev_to_curr = ΔR_total^T`, was derived from first principles (not assumed) and independently verified three ways: hand-computed sign-of-displacement checks (a camera yawing right must show a fixed forward point drifting left in its own new frame — confirmed), analytical 90° yaw/roll cases matching exact closed-form rotation matrices, and an end-to-end synthetic-rotation test that recovers >90% `agreement_fraction` after compensation from a baseline near 0. **Zero-order hold, never extrapolated**: each sample's `Δt_k` spans only from the previous sample (or previous frame) to its own timestamp — the residual gap after the last sample is left honestly uncompensated, per the architect's explicit "do not assume one sample represents the whole interval."
>
> **Sample selection** (`select_motion_hint_samples`) enforces the frozen timestamp contract — seconds, one monotonic sensor-time domain, a tightened precondition specific to E5's own arithmetic, layered on top of (not retroactively changing) E1-E4's fully opaque timestamp convention. A sample is admitted only inside the half-open interval `(previous_frame_timestamp, current_frame_timestamp]`, processed in the order given (never pre-sorted, so a misbehaving caller's non-monotonic sequence is caught, not silently fixed), rejecting invalid/missing-timestamp/out-of-interval/non-monotonic/duplicate samples via one deterministic pass.

> **`compensate_prior_geometry`** back-projects the previous frame's decimated depth snapshot into 3D camera-frame points (reusing the exact `f=abs(Q[2,3])`, `cx=-Q[0,3]`, `cy=-Q[1,3]` rectified-intrinsics derivation `DepthEstimator`/`StereoExtrinsics` already use, computed once in `__init__`), rotates by `ΔR_prev_to_curr`, and re-projects onto the current frame's own decimated grid — fully vectorized, deterministic nearest-wins occlusion handling via stable sort + fancy-index assignment (no interpolation, no hole-filling, no fabricated geometry). Structurally proven translation-free (AST identifier scan, not a text search that would false-positive on its own docstring).
>
> **Upstream of E3/E4, zero duplication:** `temporal/consistency.py` and `temporal/stabilization.py` are byte-for-byte unmodified by this phase — `pipeline.py` only decides, via a `dataclasses.replace()` substitution, which `TemporalRecord` value gets passed into their existing, frozen function signatures. ## Implemented and verified

- Standalone, ROS-free, pip-installable stereo depth library (`pip install -e .` — real venv, real hardware, no MP01 workspace needed).
- One canonical execution path: `DepthPerceptionPipeline.process()`/`.process_observation()` (stateful, recommended) and `pipeline.api`'s five stateless functions (one-shot use) — call the same underlying stage classes, no divergent logic.
- Real algorithm, not a stub: rectification → StereoSGBM disparity → closed-form Q-matrix depth → 3×3 region classification (Laplacian-variance texture, Sobel gradient, Shannon entropy, blended confidence) → 20-beam obstacle scan (IQR-percentile, EMA-smoothed, debounced).
- Math verified two ways: differentially against `cv2.reprojectImageTo3D` across real + synthetic Q matrices and invalid/negative/near-zero/huge-disparity edge cases (`test_depth_estimator.py::TestZOnlyMatchesFullReprojection`), and — added in this pass — a pure hand-computed analytic check (`TestAnalyticKnownDepth`) independent of any OpenCV reprojection function, `depth = f × baseline / disparity`, across four known focal-length/baseline/disparity combinations.
- Verified on real hardware (2026-08-05, this recovery pass's preceding session): a real USB global-shutter stereo camera, `/dev/video0`, produced a stable 1.21 m reading (±2 mm across 8 consecutive frames) against a real wall, with physically sensible region classification (wall correctly `PROBABLE_WALL`/`UNKNOWN`, a cable correctly `OBSTACLE`) and one live catch of the anti-false-clear safety design (a noisy long-range disparity blip correctly downgraded to `BLOCKED` rather than trusted as `CLEAR`).
- 131 tests, `pytest tests/ -q`, all passing as of this pass — up from 67 before it. Real behavioral coverage (a genuine rectification-failure-propagates regression test, real classification-logic tests for the `UNKNOWN` hard gate and `evidence_lost` debounce bypass), not just structural/shape assertions.
- Config validated at construction (`PipelineConfig.__post_init__`, added this pass) — bad thresholds fail immediately with a readable message instead of three layers deeper inside `DisparityEngine`.

## Partially implemented / known limitations (not fixed in this pass — documented, not hidden)

- **`traversability_mask` naming wart.** The field holds a `TraversabilityResult` (region grid + navigation decision), not a pixel mask. Not renamed because `mp01_perception` reads this field by name today, and this recovery task's explicit scope excludes touching `mp01_perception`. A rename would need a coordinated two-repo change with a documented migration.
- **No NaN/Inf validation on `StereoCalibration`'s matrices.** Shape and positivity are checked; individual finite-value validation is not.
- **Calibration loading assumes pre-rectified input** (`R1`/`R2`/`P1`/`P2`/`Q` already computed by an external tool) — no path to compute these from raw intrinsics + extrinsics via `cv2.stereoRectify()` inside this library. Pre-existing design choice, not a defect from this pass, but worth knowing before wiring in a calibration source that only provides raw `R`/`T`.
- **`DistanceReader` is real, tested (added this pass — was previously the one real gap in test coverage), and used by `examples/live_demo.py`, but not part of `DepthPerceptionResult`.** A caller wanting a single-point distance reading must construct and call it separately; it is not merged into the canonical per-frame output, by design (see `docs/ARCHITECTURE.md`).
- **`docs/INTEGRATION_READINESS.md` describes a *planned* `mp01_perception` integration that has, in fact, already happened** — flagged with a status-update note at the top of that file rather than rewritten, since rewriting it would mean describing `mp01_perception`'s current internals in detail, and this pass's scope is this repo, not that one.
- **`mp01_perception` currently imports one internal module directly** (`depth_perception_engine.quality.frame_quality.looks_like_garbage_frame`, not re-exported from the top-level `__all__`) — pre-dates this recovery pass, contradicts the long-term goal that `mp01_perception` should only ever import the top-level public API, explicitly out of scope to fix here (would require touching `mp01_perception`).
- **No config serialization/hash support.** `PipelineConfig` is a plain validated dataclass; there's no `.to_dict()`/reproducibility-hash helper. Not needed for anything in this pass's scope; would matter once configs start being logged/compared across research runs.
